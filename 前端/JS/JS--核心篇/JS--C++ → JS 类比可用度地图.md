# JS--C++ → JS 类比可用度地图

> 用法：写 JS 时冒出“这个和 C++ 的 XX 一样吧”的念头，先查对应行，再看差异栏。
> 覆盖范围：基础篇与 Web APIs 第 1-123 集；第七节补充进阶篇第 152-198 集，沿用课程编号。
> 参照：以 C++17 标准库为主，需要 C++20 的地方单独标注。不要求熟悉 GUI 框架。
> 来源：MDN JavaScript / Web API 文档、C++ Core Guidelines。可用度是教学判断，不代表两门语言的语义完全相同。

## 可用度图例

| 标记 | 含义 | 建议 |
| --- | --- | --- |
| ✅ | 可以迁移核心思路 | 仍需看清类型、返回值和生命周期 |

## 一、总表

| C++ 里的东西 | JS 对应物 | 可用度 | 差在哪 | 讲于 |
| --- | --- | --- | --- | --- |
| `auto x = 1;` / 显式类型声明 | `let` / `const` | ⚠️ | `auto` 推导后类型确定；JS 变量可绑定不同类型的值。JS 的 `const` 禁止重新赋值，不冻结对象 | 基础篇 |
| 静态类型检查与编译诊断 | 动态类型与运行时检查 | ❌ | JS 值有类型，但变量无固定类型。未声明标识符通常抛 `ReferenceError`；不存在的普通属性通常读到 `undefined`；无效事件名可能没有报错 | 全篇 |
| `std::vector<T>` 的索引访问 | 数组 | ⚠️ | JS 可混装类型、存在空槽，`length` 可写；数组越界读取通常是 `undefined`。C++ `operator[]` 越界是未定义行为，`at()` 会检查 | 基础篇 |
| `std::find_if` 返回迭代器，失败返回 `end()` | `querySelector` | ⚠️ | JS 返回第一个匹配元素或 `null`；非法 CSS 选择器会抛异常，不能说“一律不抛” | ② |
| 范围 `for` / 迭代器遍历 | `for` / `for...of` / NodeList 遍历 | ⚠️ | `querySelectorAll` 返回静态 NodeList，非 Array；可迭代且有 `forEach`，但没有数组的 `push` / `map` | ② |
| 标准库无 GUI 文本控件 | `el.innerText` / `textContent` | ❌ | 这是浏览器 DOM 能力。`innerText` 受渲染影响，`textContent` 处理文本节点；`innerHTML` 会解析标记，不应拼接不可信输入 | ③ |
| 标准库无 CSS 样式系统 | `el.style.backgroundColor` | ❌ | JS 属性采用驼峰名；需要长度单位的非零值通常要带单位，颜色等值不带长度单位。`style` 只表示行内样式，计算样式用 `getComputedStyle` | ⑤ |
| 给对象成员赋值 | `el.src` / `el.disabled` | ⚠️ | 赋值思路可借，DOM 属性有自身转换规则。布尔属性优先传布尔值；字符串 `"false"` 是真值；`className`、`htmlFor` 是 DOM 名称 | ④ |
| 给结构体增加业务字段 / 维护关联表 | `el.dataset.xxx` | ⚠️ | DOM 的 `data-*` 是字符串接口；多个命名值可以共存，连字符名称映射到驼峰键 | ⑧ |
| 函数对象、回调注册表（自行实现） | `addEventListener('click', fn)` | ⚠️ | C++17 无标准 GUI 事件订阅机制；DOM 管理监听器列表，同一目标、类型、回调和 capture 的重复注册不再添加 | ⑩ |
| 按句柄取消注册（自行实现） | `removeEventListener` | ⚠️ | DOM 要匹配事件类型、同一回调对象和 capture；重新写一个相同函数体不等于同一回调 | ⑰ |
| 回调签名由库约定 | `function (e) {}` | ⚠️ | DOM 给函数监听器传 Event 对象；`e.target` 是事件目标，`e.currentTarget` 是当前监听器注册所在的目标 | ⑭ |
| `sleep_for` / 定时任务线程 | `setTimeout` / `setInterval` | ❌ | 定时器调度回调，不阻塞当前函数等待。主线程忙时回调会延后；指定延时不是精准执行时刻，也不是独立线程 | ⑨ |
| 函数指针 / Lambda / `std::function` | 回调函数 | ✅ | 可迁移“把行为作为参数”的思路；JS 函数本身是对象，不需要 `std::function` 包装 | ⑨⑩ |
| 标准库无鼠标进入 / 离开事件 | `mouseenter` / `mouseleave` | ❌ | 按 DOM 规则学习；它们不冒泡，不能直接套用 `mouseover` / `mouseout` 的传播行为 | ⑪ |
| 高频输入回调（由具体库提供） | `mousemove` | ⚠️ | 避免每次事件做大量计算；不要假定每次物理移动都恰好产生一个事件 | ⑪ |
| 标准库无输入焦点事件 | `focus` / `blur` | ❌ | 两者不冒泡且不可取消；需要冒泡可考虑 `focusin` / `focusout` | ⑫ |
| 标准库无键盘按下 / 松开事件 | `keydown` / `keyup` | ❌ | 由浏览器输入系统提供；`keypress` 已废弃。文本输入应考虑 `input` 和组合输入事件 | ⑬ |
| 输入库的键值枚举（因库而异） | `e.key` / `e.code` | ⚠️ | `key` 是按键含义，`code` 偏向物理键位；使用 `e.key === 'Enter'`，不要依赖已废弃的 `keyCode` | ⑬ |
| `nullptr` / `std::optional<T>` | `null` / `undefined` | ⚠️ | 只可借“缺失值”思路。声明未初始化的变量值为 `undefined`；未声明名字不是同一回事，直接读通常抛 `ReferenceError` | ⑭ |
| 回调的取消标志（由库约定） | `e.preventDefault()` | ⚠️ | 标准 C++ 没有通用对应；只对可取消事件有效，被动监听器中不能这样取消。阻止默认行为与阻止传播是两件事 | ⑲ |
| 程序初始化 / 资源加载阶段 | `DOMContentLoaded` / `load` | ⚠️ | DOM 解析及相关延迟脚本就绪，与依赖资源加载完成，是不同事件时机；不是 C++ 的对象构造阶段 | ⑳ |
| GUI 库的局部 / 全局坐标（因库而异） | `offsetX/Y` / `clientX/Y` / `pageX/Y` | ⚠️ | 标准库无对应坐标约定；分别确认事件目标、视口、文档等参照系，`offsetX/Y` 不应当作监听容器坐标 | ㉑ |
| 标准库无盒模型客户区 | `el.clientWidth` | ❌ | 包含内边距，不含边框与垂直滚动条；结果为整数 | ㉑ |
| 标准库无元素布局尺寸 | `el.offsetWidth` | ❌ | 通常包括内边距、边框和垂直滚动条；取整数。需要变换后的边界或小数时考虑 `getBoundingClientRect()` | ㉑ |
| 对象持有的相对位置字段（自行约定） | `el.offsetLeft` / `offsetTop` | ❌ | 偏移参照是 `offsetParent`，不能简单等同父元素；需按定位和布局规则理解 | ㉑ |
| `system_clock` + `time_t` / `std::tm` | `new Date()` | ⚠️ | `std::tm::tm_mon` 和 JS `getMonth()` 都是 0-11；`tm_mday` 对 `getDate()`，`tm_wday` 对 `getDay()`；本地时区与 UTC 方法要区分 | ㉒ |
| 用 chrono 获取并转换时间间隔 | `Date.now()` / `d.getTime()` | ⚠️ | JS 明确定义为 Unix 纪元起的毫秒数。C++17 不应把 `system_clock` 的纪元、原始 `count()` 单位假定为 Unix 毫秒；C++20 的 system_clock 采用 Unix 时间 | ㉓ |
| `duration::count()` / 时钟 tick | JS 时间戳 | ❌ | `count()` 的单位由 duration 的 period 决定，不是统一的毫秒；时钟和纪元也必须匹配后才能换算 | ㉓ |
| `steady_clock` 计时 / 遍历 vector 时 erase | `performance.now()` / 遍历实时 `childNodes` 时删除 | ⚠️ | 测耗时优先单调时钟；`Date.now()` 是墙钟。C++ 容器有迭代器失效规则；DOM 实时列表删除会移动后续索引，正向循环可能漏删 | ㉓㉔ |
| 第三方 XML / 树结构库 | `parentNode` / `childNodes` / `firstChild` / `nextSibling` | ⚠️ | 只借树遍历思路；C++17 标准库没有 DOM/XML 解析器，不能假定第三方接口和节点规则一致 | ㉔ |
| XML 库的空白保留选项（因库而异） | DOM 文本节点 | ⚠️ | HTML 中源码换行、空格可能形成文本节点；只要元素用 `children` / `firstElementChild`，不要假定 `childNodes` 全是标签 | ㉔ |
| 创建树节点，再挂接到父节点 | `createElement` + `appendChild` | ✅ | 思路可迁移；已有 DOM 节点再次 append 是移动。JS 对象生命周期不由 append 时转交 unique_ptr 那样决定 | ㉕ |
| `vector::insert(pos, value)` / 树插入 | `insertBefore(newNode, refNode)` | ⚠️ | DOM 用参考节点，不是数值下标。没有 `insertAfter` 方法，可用 `after()` 或 `insertBefore(node, ref.nextSibling)` | ㉕ |
| 从容器 erase / 断开树链接 | `removeChild` / `remove()` | ⚠️ | DOM 删除是断开链接，不是 C++ `delete`。其他引用仍可持有节点；`removeChild` 返回节点并保留其监听器 | ㉕ |
| 拷贝构造 / 自定义 clone | `cloneNode(false/true)` | ⚠️ | DOM clone 按节点规则复制；true 包含后代。不会复制 `addEventListener` 注册的监听器，可能复制出重复 id；不同于 C++ 成员逐个拷贝 | ㉕ |
| 输入库可能合成鼠标事件 | touch 与兼容鼠标 / click 事件 | ⚠️ | 同一交互可能触发多套监听逻辑；不能假定每次触摸必然双触发。统一输入可考虑 Pointer Events | ㉖ |
| 引入依赖、满足约定、传配置 | 引库并创建 Swiper 实例 | ✅ | 思路可迁移；CDN/模块加载与 C++ 链接不同，配置项是否检查取决于库和工具 | ㉗ |
| 虚函数多态 | 事件委托 | ❌ | 前者是类型与动态分派，后者是 DOM 包含关系与事件传播；见第二节 | ⑱ |
| 标准 C++ 无 DOM 事件传播模型 | 捕获 / 目标 / 冒泡 | ❌ | 不要把普通回调列表当成有传播路径的事件树 | ⑯ |
| 成员函数的 `this` 指针 | JS `this` 值 | ❌ | C++ 非静态成员函数操作调用所指定的对象；JS 普通函数的 this 通常由调用形式决定，箭头函数另有规则 | ⑮ |

## 二、专项：多态 vs 事件委托

**像的部分**：都能让一段上层逻辑处理多个对象，但这是架构上的相似，不是语言机制相同。

| 维度 | C++ 多态 | DOM 事件委托 |
| --- | --- | --- |
| “上层”是什么 | 基类与派生类的类型关系 | DOM 容器与后代的包含关系 |
| 谁做分派 | 通过基类指针 / 引用调用虚函数，按动态类型选最终覆盖函数；不要求实现必须采用虚表 | 浏览器传播事件，监听器再用 `target` / `closest()` 判断业务目标 |
| 到达几个处理者 | 一次虚调用选择一个最终覆盖函数 | 沿传播路径可能触发多个监听器，受冒泡、捕获和停止传播影响 |
| 对象之间的关系 | `Dog` 是 `Animal` | `li` 被 `ul` 包含，不是它的派生类型 |

标准 C++ 没有 DOM 路由事件的直接对应物。可以想象一棵节点树和一条从目标到祖先的路径，但这需要程序自己实现；不是继承语法自动提供的能力。

**异常沿调用栈传播也只能有限类比**：C++ 异常沿调用栈寻找匹配处理器，DOM 事件沿节点树传播。两条路径、处理规则和停止条件都不同，不能用 `catch` 推导冒泡规则。

实际委托时要确认事件是否冒泡；`target` 可能是按钮内部的图标。可用 `closest()` 找业务元素，再检查它确实属于当前容器。

## 三、专项：`this` 为什么不能照搬

| 维度 | C++ | JS |
| --- | --- | --- |
| 基本含义 | 非静态成员函数中指向当前对象的指针 | 普通函数调用中的接收者值；不一定是对象 |
| 与调用的关系 | `obj.method()` 的当前对象是 obj，虚函数再根据动态类型选实现 | `obj.fn()`、独立调用、`call` / `apply` / `bind`、`new` 有不同规则 |
| 独立使用方法 | 非静态成员函数指针需要结合对象调用，不是普通函数指针 | `const f = obj.fn; f()` 会丢失原接收者；严格模式下通常为 undefined，非严格普通函数通常为全局对象 |
| Lambda / 箭头函数 | `[this]` 捕获指针，必须保证对象存活；`[*this]`（C++17）捕获对象副本 | 箭头函数没有自己的 this，沿词法环境使用外层 this |
| DOM 函数监听器 | 标准库无此约定 | 普通函数监听器调用时 this 通常等于 `e.currentTarget`；箭头函数不遵循这个接收者绑定 |

不要把 C++ `std::bind` 与 JS `bind` 当成完全一致：前者绑定可调用对象与参数；后者对普通函数预设 this 和参数，并返回新函数。箭头函数的 this 不能被 bind 改写。

**实战结论**：DOM 监听器中，用 `e.currentTarget` 表达“监听器所在的元素”通常更直接；用 `e.target` 表达事件目标。异步回调里若还要使用 currentTarget，应在监听器执行时保存需要的值。

## 四、可以放心借过来的东西

| 你的 C++ 经验 | 在 JS 里的落点 |
| --- | --- |
| 用第三方 JSON 库序列化 / 解析 | `JSON.parse` / `JSON.stringify`；C++17 标准库无 JSON 库，不要假定能无损保存全部 JS 类型 |
| `std::transform` / `copy_if` / `accumulate` | `map` / `filter` / `reduce`；返回容器、修改目标和空输入行为要单独确认 |
| 调试器断点 / `std::cerr` / 日志库 | 浏览器断点与 Console；Network 面板检查请求、响应和状态 |
| `std::future` / `std::async` | 可借异步结果思路；Promise 不等于线程任务，也不意味着并行。JS async/await 需另行补充 |
| `std::unique_ptr` / `shared_ptr` 的所有权意识 | 仍要留意谁持有对象、监听器和闭包；但 JS 用可达性 GC，不靠引用计数归零或离开作用域及时析构 |
| HTTP 客户端 / 服务端协议知识 | 前端通过 HTTP 调用后端，语言不限定为 C++；请求与响应的数据格式仍要双方约定 |

## 五、一条别混淆的名字

| 名字 | 指什么 |
| --- | --- |
| Web API（常见后端语境） | 经 HTTP 暴露的接口，例如路由接收请求、返回 JSON；可由多种后端语言实现 |
| Web APIs（本课程语境） | 浏览器提供给 JS 的能力，例如 DOM、事件、定时器和存储；课程有时还混合讲 JS 内置库 |

这里只是教学语境区分，**不能只凭有没有字母 s 判断技术类别**。正则、JSON、Date 属于 JavaScript 内置能力，不是 DOM API。

浏览器端最终可以调用服务端 HTTP 接口；这与 C++ 类的成员接口不是同一层概念。

## 六、一条已经反复出现的“元规律”

❌ 和 ⚠️ 主要集中在三类地方：

1. **类型与生命周期**：C++ 有静态类型、值语义、RAII 和容器失效规则；JS 有动态类型、对象共享和可达性 GC。C++ 出错也不总会抛异常，未定义行为尤其不能当成安全检查。
2. **名字与配置**：JS 未声明标识符可能立即抛错，但对象拼错属性可能得到 undefined，事件名或配置项拼错则可能没有反馈。不能概括为“JS 从不报错”。
3. **同名不同义**：`const`、`new`、`this`、拷贝和继承都要重新确认。C++ 的 `tm_mon` 与 JS 月份编号反而相同，都是从 0 开始，别记反。

实战习惯：先确认代码确实执行，再检查值和类型。用 Console、断点和 Network 验证假设；不要把 JS 的静默行为套到 C++，也不要把 C++ 的编译期约束套回 JS。

## 七、进阶篇新增对照（第 152-198 集）

本节承接总表。✅ 表示核心思路可借，并不意味着类型系统、生命周期和全部边界条件相同。

### 第 152-160 集：作用域 · 闭包 · 解构

| C++ 里的东西 | JS 对应物 | 可用度 | 差在哪 | 讲于 |
| --- | --- | --- | --- | --- |
| 嵌套块与词法名字查找 | 作用域链 | ✅ | 可借词法嵌套思路；JS 的 var 不采用普通块作用域，let/const 有暂时性死区 | 152 |
| 块作用域局部变量 | let / const | ⚠️ | JS 离开块不保证对象立即销毁；闭包可以继续持有绑定。C++ 局部对象通常在作用域结束时析构 | 152 |
| RAII / unique_ptr / shared_ptr | GC 与可达性 | ❌ | C++17 不内置通用追踪 GC；JS 可回收不可达循环，不依赖 shared_ptr 式引用计数。外部资源仍应显式关闭或注销 | 153 |
| Lambda 的值捕获 / 引用捕获 | 闭包 | ⚠️ | JS 没有显式捕获列表，闭包访问词法绑定；C++ 引用捕获可能悬空，JS 捕获的环境可延长可达生命周期 | 154 |
| 名字通常须先声明再使用 | hoisting 提升 | ❌ | 函数声明、var、let/const 不同；var 声明提前可见但值起初为 undefined，let/const 初始化前访问会抛错 | 155 |
| 接收 vector / initializer_list / 可变参数模板 | 剩余参数 `...nums` | ⚠️ | JS 收集为真数组；C++ 参数包不是运行时异质数组，initializer_list 与 vector 也有不同类型约束 | 156 |
| 参数包展开 `args...` / 容器拷贝 | 展开 `...` | ⚠️ | C++ 参数包展开依赖模板；JS 在运行时展开可迭代对象，数组/对象复制通常是浅层复制 | 156 |
