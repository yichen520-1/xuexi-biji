# TS：映射、条件与工具类型

> **定位**：以 JS 为运行基础、C++17 为对照理解静态类型；示例按 TypeScript 5.9.3 验证，不宣称为最新版本。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

映射类型遍历某组键，重新组织对象类型；条件类型根据类型关系选择分支。常见工具类型是这些基础机制的组合，不是魔法。先问要表达的业务变化是什么，再选工具，而不是看到 Partial 就把全部字段都变成可选。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```ts
interface User { id: number; name: string; email: string }
type CreateUser = Omit<User, 'id'>;
type UpdateUser = Partial<Pick<User, 'name' | 'email'>>;
type UserSummary = Pick<User, 'id' | 'name'>;
type Flags<T> = { [K in keyof T]: boolean };
type FormFlags = Flags<CreateUser>;
type ElementOf<T> = T extends readonly (infer U)[] ? U : never;
type Name = ElementOf<readonly string[]>;

const flags: FormFlags = { name: false, email: true };
const name: Name = '小陈';
console.log(flags, name);
```

`Pick` 选字段，`Omit` 去字段，`Partial` 改为可选，`Record<K,V>` 给一组键统一值类型，`ReturnType<F>` 从函数类型取返回值，`Awaited<T>` 解开 Promise 的值类型。它们都只改变描述，不复制、过滤或验证实际对象。

### 2. 条件类型的分配行为

当条件左侧是裸类型参数时，联合常被逐成员处理。例如 `T extends string ? ... : ...` 在 T 为联合时会分发；想整体比较可写 `[T] extends [string]`。这是类型计算规则，不是 JS 的 if。

---

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

- `Partial<User>` 适合部分更新，但未必适合创建表单；创建时缺失必填字段可能是错误设计。
- 工具类型一般是浅层的，`Readonly<T>` 不自动递归到所有嵌套对象。
- `Omit` 不会在运行时删除密码字段。真正对外输出对象时仍需显式构造允许暴露的字段。

<span style="background-color:rgb(255, 249, 227)">四：动手练习</span>

设计用户修改参数：id 必填，name 和 email 可选。

> [!success]- 参考答案
> `type Patch = Pick<User, 'id'> & Partial<Pick<User, 'name' | 'email'>>`。不要把 id 一起 Partial 掉。
