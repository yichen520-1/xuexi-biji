# TS：收窄、业务状态与穷尽检查

> **定位**：以 JS 为运行基础、C++17 为对照理解静态类型；示例按 TypeScript 5.9.3 验证，不宣称为最新版本。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

类型收窄根据运行时证据减少可能性，例如 `typeof`、`instanceof`、`in`、字面量比较和自定义守卫。**可辨识联合**让每个状态带一个固定标签，关联该状态专属的数据，避免多个布尔值组合出矛盾界面。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```ts
type LoadState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; message: string };

function assertNever(value: never): never {
  throw new Error(`未处理状态：${JSON.stringify(value)}`);
}
function describe(state: LoadState<readonly string[]>): string {
  switch (state.status) {
    case 'idle': return '尚未加载';
    case 'loading': return '加载中';
    case 'success': return `共 ${state.data.length} 条`;
    case 'error': return state.message;
    default: return assertNever(state);
  }
}
console.log(describe({ status: 'success', data: ['TS'] }));
```

标签为 success 才有 data；类型直接表达“失败时没有成功数据”的事实。以后加一个 `cancelled` 分支但忘改 switch，传给 assertNever 的值就不再是 never，检查器可提示漏分支。

---

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

- 自定义 `value is User` 守卫是你向检查器作出的承诺；实现不正确会让后续代码错误地得到信任。不要返回一个固定 true。
- `instanceof` 适合真实构造函数实例；从 JSON 得到的普通对象即使字段相同，也不是自动变成类实例。
- 可对照 C++17 的 `std::variant` 与访问者，但 TS 不创建额外的运行时变体容器，标签必须由你写进对象。
