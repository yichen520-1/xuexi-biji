# TS：标准装饰器与旧装饰器

> **定位**：以 JS 为运行基础、C++17 为对照理解静态类型；示例按 TypeScript 5.9.3 验证，不宣称为最新版本。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

这篇对应速通课的 **P4 装饰器附加篇**。装饰器会在类定义等相关阶段参与运行，不是纯类型标注。TypeScript5 支持的标准装饰器语义，与 `experimentalDecorators` 对应的旧实现签名和能力不同；学习旧课或第三方框架时，先确认是哪一套。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```ts
function logged(
  original: (this: Counter) => number,
  context: ClassMethodDecoratorContext<Counter, (this: Counter) => number>,
) {
  return function (this: Counter): number {
    console.log(`调用 ${String(context.name)}`);
    return original.call(this);
  };
}
class Counter {
  private value = 0;
  @logged
  increment(): number { return ++this.value; }
}
console.log(new Counter().increment());
```

这是标准方法装饰器示例：接收原方法和 context，返回替代方法；替代函数显式把 this 交回原方法。不要用箭头函数无意捕获装饰器外层 this。

| 比较 | 标准装饰器 | 旧装饰器 |
| --- | --- | --- |
| 常见签名 | value 与 context | target、key、descriptor 等 |
| 开关 | 本示例不启用 experimentalDecorators | 通常显式启用该开关 |
| 参数装饰器 | 不支持旧式参数装饰器 | 支持旧方案的相关能力 |
| 元数据 | 不等同 emitDecoratorMetadata | 某些库依赖旧元数据配置 |

---

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

标准装饰器不能与旧的 `emitDecoratorMetadata` 使用方式混为一谈。框架提供的 `@xxx` 也有自己的契约，不能只凭标点相同就互换教程。要核对 TypeScript 版本、编译配置与依赖文档。

---

<span style="background-color:rgb(255, 249, 227)">四：动手练习</span>

为什么把旧教程里的 `(target, key, descriptor)` 原样用于本例可能报错？

> [!success]- 参考答案
> 两套调用协议不同。不是参数名拼错，而是装饰器语义与配置不匹配；先确认框架要求，不能靠 any 掩盖。
