# TS：泛型约束与类型关系

> **定位**：以 JS 为运行基础、C++17 为对照理解静态类型；示例按 TypeScript 5.9.3 验证，不宣称为最新版本。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

泛型最重要的价值是保存输入、输出之间的关系，不是把所有位置都换成字母 T。返回 `any` 会丢失关系；返回 `unknown` 虽安全但需要调用者重新检查；泛型能让已知结构贯穿函数调用。TS 泛型主要被擦除，不像 C++ 模板普遍按实参生成独立实现。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```ts
function first<T>(items: readonly T[]): T | undefined {
  return items[0];
}
function pick<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}
interface HasId { id: number }
function findById<T extends HasId>(items: readonly T[], id: number): T | undefined {
  return items.find(item => item.id === id);
}
const user = { id: 1, name: '小陈' };
const name = pick(user, 'name');
console.log(name.toUpperCase(), first([1, 2]));
```

`K extends keyof T` 把 key 限制为对象已有键；`T[K]` 表达对应属性的值类型。`findById` 只要求元素有数字 id，但保留其他字段，返回结果仍是原元素类型。

### 2. 约束不能凭空制造 T

`T extends HasId` 只说明所有 T 都有 id，不说明 `{ id: 1 }` 就能当任意 T。调用者可能选择还必须包含 name 的类型，因此泛型函数不能仅靠最低约束构造完整 T。

---

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

- 类型参数若只出现一次，可能根本没有表达关系，普通参数类型更清楚。
- 约束不是运行时验证；外部数据仍需要检查。
- 没有元素时返回 `undefined` 是真实语义，不应为了漂亮返回类型加 `!`。
- `Array<T>` 和 `T[]` 对普通数组通常等价；只读能力需要另写 `ReadonlyArray<T>` 或 `readonly T[]`。

---

<span style="background-color:rgb(255, 249, 227)">四：动手练习</span>

写 `last<T>`，要求接受只读数组并保留元素类型。

> [!success]- 参考答案
> `function last<T>(items: readonly T[]): T | undefined { return items[items.length - 1]; }`。空数组仍需表达为 undefined。
