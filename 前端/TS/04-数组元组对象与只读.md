# TS：数组、元组、对象与只读

> **定位**：以 JS 为运行基础、C++17 为对照理解静态类型；示例按 TypeScript 5.9.3 验证，不宣称为最新版本。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

数组描述“任意长度、元素受某种类型约束”的序列；元组描述各位置的不同含义和常见固定长度。两者运行时都还是 JS 数组。`readonly` 是检查层对写入能力的限制，不会自动调用 `Object.freeze`，也不能控制所有别名。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```ts
type Point = readonly [x: number, y: number];
interface Task {
  readonly id: number;
  title: string;
  tags?: string[];
}
const origin: Point = [0, 0];
const tasks: Task[] = [{ id: 1, title: '学习 TS' }];

function firstTitle(items: readonly Task[]): string {
  return items[0]?.title ?? '暂无任务';
}
console.log(origin[0], firstTitle(tasks));
```

`noUncheckedIndexedAccess` 开启时，普通数组索引读取会提醒元素可能不存在。不要把“数组类型是 `Task[]`”理解成“任何整数下标一定有 Task”。元组有已知位置时检查会更精确。

### 2. 修改容器与修改元素是两层权限

参数是 `readonly Task[]` 会禁止 `push`、`splice` 等容器操作，但不自动让每个 Task 的 `title` 只读。要递归只读需设计更深层的类型，并决定运行时是否也冻结；一层 `Readonly<T>` 不是深冻结。

---

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

| 对照 | 可以借用的直觉 | 必须放弃的直觉 |
| --- | --- | --- |
| `Task[]` 与 `std::vector<Task>` | 同类元素序列 | JS 数组不是 C++ 连续对象存储模型 |
| 元组与 `std::tuple` | 位置有独立含义 | TS 元组运行时仍是普通数组 |
| readonly 与 const | 限制某些写入 | 不代表深层不可变或内存保护 |
