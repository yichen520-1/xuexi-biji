# TS：编译流程与类型边界

> **定位**：以 JS 为运行基础、C++17 为对照理解静态类型；示例按 TypeScript 5.9.3 验证，不宣称为最新版本。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

### 1. TS 增加的是检查层，不是另一套运行时

TypeScript 在 JavaScript 语法上增加类型描述。类型检查器分析程序，编译器把类型标注等语法擦除或转译成 JS；浏览器和 Node 最终执行的是 JS。`number` 不能限制值必须为整数，也不会让 JS 数字变成 C++ 的 `int`。

| 阶段 | 做什么 | 不负责什么 |
| --- | --- | --- |
| 类型检查 | 检查参数、属性和赋值关系 | 不验证服务器实际返回的数据 |
| 编译/构建 | 生成能运行的 JS | 不自动修正业务逻辑 |
| 运行 | 按 JS 语义执行 | 不保留 interface 帮你检查对象 |

**与 C++17 的关键差异**：C++ 类型通常参与存储布局、重载选择和生成代码；TS 很多类型只参与检查。不要把“编译通过”误解为有运行时类型保护。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```ts
interface User { id: number; name: string }
function greet(user: User): string {
  return `你好，${user.name}`;
}
const user: User = { id: 1, name: '小陈' };
console.log(greet(user));
```

1. 检查器验证对象具有 `id`、`name`，并核对返回值为字符串。
2. 输出 JS 时 interface 和 `: User` 等标注不再存在。
3. 运行时只剩对象和函数；如果外部数据的 `name` 为数字，必须自己验证。

**本地步骤**：在“示例”目录执行 `npm ci` → `npm run check` → `npm run build` → `npm start`。`check` 不生成文件，`build` 的 `noEmitOnError` 阻止带类型错误的输出。Vite 等工具转译很快，但不能因此省略独立类型检查。

---

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

- `.ts` 文件不能不经环境支持就当普通脚本丢给浏览器；本套笔记通过构建生成 JS。
- `as User` 是断言，不会调用一个检查 User 的构造过程。
- TS 的类型错误和 JS 的语法/运行错误是不同层面；只把报错关掉不等于解决问题。

---

<span style="background-color:rgb(255, 249, 227)">四：动手练习</span>

把 `name` 改成数字，分别观察类型检查和生成 JS 的变化。再回答：为什么即使接口声明正确，网络数据仍要校验？

> [!success]- 参考答案
> 数字与 `string` 不兼容，检查失败；类型在运行时被擦除，外部输入不会主动遵守本地声明，因此需要运行时验证。
