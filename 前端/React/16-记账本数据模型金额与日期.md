# React：记账本数据模型、金额与日期

> **版本口径**：按指定 React18 课程讲解，示例固定 React 18.3.1、Router 6；与 React19 的差异单独说明。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

记账数据要先约定：金额用正的整数分，收支由独立 type 表示；时间字段明确是发生日期还是精确时间戳；分类 id 与展示名称分开。不要让负金额与 type 双重表达方向，造成一会相加一会取反的混乱。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```ts
export interface Bill {
  id: string;
  type: 'income' | 'expense';
  amountCents: number;
  date: string; // 教学模型：本地日历日 YYYY-MM-DD
  categoryId: string;
}
export function summarize(bills: readonly Bill[]) {
  return bills.reduce((result, bill) => {
    if (bill.type === 'income') result.income += bill.amountCents;
    else result.expense += bill.amountCents;
    return result;
  }, { income: 0, expense: 0 });
}
```

这里 reducer 累加的是新创建的本地结果对象，不是直接修改 React state，因而合理。余额再由 income - expense 推导，不单独存第三份可写值。

### 2. 日期不是一个无条件可切片的字符串

若模型保存的是本地 YYYY-MM-DD，可按前 7 字符分月，前提是输入已校验。若服务器传 ISO 时间戳，应先按业务时区解释再分组；直接 `toISOString()` 使用 UTC，可能把本地跨午夜记录分到另一天。

---

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

金额输入先保留字符串。转换时校验最多两位小数、非负范围与安全整数；`parseFloat('12abc')` 可能得到 12，不是严格的金额校验。演示项目不声称具备专业多币种、税率或财务精度能力。
