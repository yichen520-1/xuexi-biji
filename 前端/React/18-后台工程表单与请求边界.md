# React：后台工程、表单与请求边界

> **版本口径**：按指定 React18 课程讲解，示例固定 React 18.3.1、Router 6；与 React19 的差异单独说明。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

后台工程可按页面、业务 API、状态、可复用组件和基础请求层划分。请求层处理 URL、响应与通用错误，业务 API 描述具体接口，页面决定用户反馈。不要把所有逻辑堆进一个 Axios 拦截器或组件 Effect。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```ts
export async function requestJson(path: string, init: RequestInit = {}): Promise<unknown> {
  const response = await fetch(path, init);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  if (response.status === 204) return null;
  return response.json();
}
```

返回 unknown 迫使业务层确认真实结构。若某 API 返回无内容，先识别 204，不能不管响应契约一律 `.json()`。完整工程还应有取消、业务错误映射和明确的认证策略，但不把未知后台字段随意编造为已核实事实。

**表单链路**：输入规则改善即时反馈；提交入口再次校验；请求完成前限制重复提交；成功后导航或刷新；失败保持必要输入并给出可操作提示。前端验证不替代服务器验证。
