# React：参数、404 与路由部署

> **版本口径**：按指定 React18 课程讲解，示例固定 React 18.3.1、Router 6；与 React19 的差异单独说明。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

路径参数表达资源身份，查询参数表达筛选/排序等可分享条件，location state 适合某次导航附带的临时上下文。是否能刷新恢复、能否复制链接、是否可被外部构造，都决定数据该放哪里。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```tsx
import { useParams, useSearchParams, Link } from 'react-router-dom';
export function Detail() {
  const { id } = useParams<'id'>();
  const [search] = useSearchParams();
  const tab = search.get('tab') ?? 'summary';
  if (!id) return <p>缺少资源编号</p>;
  return <><p>资源 {id}，标签 {tab}</p><Link to="/tasks">返回任务</Link></>;
}
```

即使 TS 标注参数名，运行时仍需处理缺失、格式错误和无权限；URL 是外部输入。搜索参数都是字符串或缺失值，页码要转数字并验证范围，不能直接当 number 使用。

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

| 模式 | 地址特点 | 部署检查 |
| --- | --- | --- |
| browser history | 路径直接在 URL 中 | 深层路径刷新需服务器回退入口 |
| hash | 路由在 # 后 | 片段不发送服务器，注意外层部署路径 |

`path: '*'` 处理前端未匹配页面，不替代服务器静态资源 404。回退也不能把每个失败 API 请求都返回 index.html，否则前端可能把 HTML 当 JSON 解析。

**反例**：客户端导航能成功，只证明应用已经加载后 Router 会处理；新标签直接打开深层地址走的是服务器入口，两条链路要分别验证。

<span style="background-color:rgb(255, 249, 227)">四：动手练习</span>

筛选条件要求发链接给同学也能复现，应放普通局部 state 还是 query？

> [!success]- 参考答案
> query 通常更合适，再把 URL 解析成界面状态；避免局部 state 和地址各持一份互不同步的源。
