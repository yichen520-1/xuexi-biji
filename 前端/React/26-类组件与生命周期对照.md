# React：类组件与生命周期对照

> **版本口径**：按指定 React18 课程讲解，示例固定 React 18.3.1、Router 6；与 React19 的差异单独说明。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

理解类组件有助于维护旧项目，但不把 Hooks 简单理解为一一替换生命周期名称。类组件用 this.state/this.props，函数组件每次渲染有独立闭包；Effect 以同步过程与依赖组织，不按“只在某某阶段执行一段”机械拆分。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```tsx
import { Component } from 'react';
type Props = { step: number };
type State = { count: number };
export class ClassCounter extends Component<Props, State> {
  override state: State = { count: 0 };
  increment = () => this.setState((current, props) => ({ count: current.count + props.step }));
  override render() {
    return <button onClick={this.increment}>{this.state.count}</button>;
  }
}
```

类 setState 的对象更新会浅合并部分状态；useState setter 替换该 Hook 的值，不能把类的浅合并行为套到函数组件。类方法中的 this 绑定也要处理，示例用箭头字段保留实例。

| 旧项目职责 | 函数组件常见表达 | 不要误解 |
| --- | --- | --- |
| 挂载/更新时同步订阅 | Effect + 正确依赖 | 不是复制三份逻辑到不同回调 |
| 卸载清理 | Effect 返回清理 | 依赖变化时也可能清理 |
| 实例字段 | ref 或模块状态，按范围决定 | 不会都自动成为响应式 |

---

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

componentDidMount 初始化外部资源，要在 componentWillUnmount 释放；依赖 props 改变时还要重新同步。不要在 render 里发请求。类名与 C++ class 相似，不代表内存布局、析构或虚表规则相同。


**严格配置补充**：本示例启用 `noImplicitOverride`，因此 `state` 与 `render` 明确标为 `override`，表示它们覆盖基类成员。这帮助发现父类接口变化，不改变 JS 的运行时分派规则。

---

<span style="background-color:rgb(255, 249, 227)">四：动手练习</span>

类 state 有 a、b 两字段，改写为单个 useState 对象后只传 `{ a: 1 }`，b 会自动保留吗？

> [!success]- 参考答案
> 不会，Hook 值会被替换；需按真实模型显式复制旧对象，或拆为独立状态。
