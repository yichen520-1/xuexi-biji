# React：列表筛选、分页、删除与过时请求

> **版本口径**：按指定 React18 课程讲解，示例固定 React 18.3.1、Router 6；与 React19 的差异单独说明。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

服务端分页至少有查询条件、页码/页大小、数据、总数与请求状态。筛选变化常需回到第一页；删除当前页最后一项可能需要回退页码。把这些关系建模清楚，比只把 Table 的 onChange 接上请求更重要。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```ts
interface Query { page: number; pageSize: number; channelId?: string; status?: string }
export function toSearch(query: Query): string {
  if (!Number.isInteger(query.page) || query.page < 1) throw new Error('页码无效');
  if (!Number.isInteger(query.pageSize) || query.pageSize < 1) throw new Error('页大小无效');
  const params = new URLSearchParams({ page: String(query.page), pageSize: String(query.pageSize) });
  if (query.channelId) params.set('channelId', query.channelId);
  if (query.status) params.set('status', query.status);
  return params.toString();
}
```

条件改变后创建新 query，Effect/请求层只根据这份明确输入加载。取消旧请求或核对 requestId，避免上一页响应晚到覆盖当前页。服务端返回的总数是查询条件下总数，不等于当前 items.length。

### 2. 删除的闭环

用户确认 → pending 防重复 → 服务器校验并删除 → 更新/重新请求 → 必要时调整页码 → 提示成功。选择乐观删除时必须保留回滚信息；不能失败了仍维持“删除成功”。

---

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

空字符串、undefined、未选择筛选项如何进入 URL 由接口契约决定；不要拼出字面量 `undefined`。日期范围还需约定时区与区间是否包含终点，不能只看日期控件上显示了什么。

<span style="background-color:rgb(255, 249, 227)">四：动手练习</span>

当前第 3 页只有 1 条，删除后为空，应该显示“暂无全部数据”吗？

> [!success]- 参考答案
> 不一定，前两页仍可能有数据。结合总数与页大小计算有效页码，必要时退到第 2 页再加载。
