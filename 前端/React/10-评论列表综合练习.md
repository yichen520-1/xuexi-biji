# React：评论列表的完整数据流

> **版本口径**：按指定 React18 课程讲解，示例固定 React 18.3.1、Router 6；与 React19 的差异单独说明。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

评论案例把列表身份、不可变更新、受控输入、筛选排序和组件通信串成闭环。真正的源状态通常是评论数组、输入草稿与排序选择；排序后的数组和总数由它们推导，不需要每项再建一套状态。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```ts
export interface Comment { id: string; text: string; createdAt: number; likes: number }
export function makeComment(text: string): Comment {
  const normalized = text.trim();
  if (!normalized) throw new Error('评论不能为空');
  return { id: crypto.randomUUID(), text: normalized, createdAt: Date.now(), likes: 0 };
}
export function sortComments(items: readonly Comment[], by: 'time' | 'likes'): Comment[] {
  return [...items].sort((a, b) => by === 'time'
    ? b.createdAt - a.createdAt : b.likes - a.likes || b.createdAt - a.createdAt);
}
```

用户提交时先生成记录，再用纯 updater 添加。时间以数值保存、显示时格式化；排序前复制；删除按 id，而不是文本。两条同名评论仍是独立记录。

**组件划分**：CommentForm 负责输入与通知；CommentList 负责映射；CommentItem 接受一条数据和删除回调；拥有评论数组的父组件负责真实修改。需要复用请求时再提取 Hook，不一开始就拆成几十层。

---

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

XSS 边界要清楚：普通 JSX 字符串会转义，不能随意用 dangerouslySetInnerHTML 渲染用户评论。前端判断“自己的评论”只控制按钮展示，后端仍要验证删除权限。

---

<span style="background-color:rgb(255, 249, 227)">四：动手练习</span>

验收：添加两条同名评论 → 给一条点赞 → 切换排序 → 删除另一条 → 清空输入并聚焦 → 检查总数。进一步模拟请求失败，确认失败不会导致已显示列表无故消失。

> [!success]- 参考答案
> 使用稳定 id、不可变更新和单一数据所有者。请求成功前是否乐观更新需显式设计，失败回滚不能由“凑巧重新请求”代替。
