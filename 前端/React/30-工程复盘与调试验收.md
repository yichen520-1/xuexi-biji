# React：工程复盘、调试与验收

> **版本口径**：按指定 React18 课程讲解，示例固定 React 18.3.1、Router 6；与 React19 的差异单独说明。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

完成课程不等于所有功能都“跑过一次”。至少要验证：源数据在哪里、每次写入谁负责、失败与取消怎样表现、刷新与导航如何恢复、外部资源怎样释放、类型与运行时边界是否明确。调试是沿数据流查证据，不是到处加 forceUpdate。

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

| 症状 | 先检查 | 常见根因 |
| --- | --- | --- |
| 点击不更新 | handler 是否执行、是否生成新状态 | 渲染时误调用、原地修改 |
| 更新后读到旧数 | 当前闭包与更新队列 | 状态快照被误当可变变量 |
| 反复请求 | Effect 读了什么、依赖引用是否稳定 | 每次新建对象、多余 Effect |
| 切页面数据乱 | 请求身份与清理 | 旧响应覆盖新查询 |
| 排序后输入错位 | key 与记录 id | 使用下标/随机 key |
| 本地正常部署失败 | 构建产物、base、服务器回退 | 把开发环境当生产环境 |

完整本地工程见 `示例/react18-ts-demo`，包含路由、Redux Toolkit 任务状态、受控输入、派生统计与按页加载示例。它不依赖课程私有接口，也不声称实现完整的极客园后台。

---

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

**验证层次**：类型检查发现契约错误；纯函数测试验证更新与计算；构建验证模块与打包；浏览器交互验证点击、焦点、导航和实际显示。某一层通过不等于其他层也已经验证。

**C++17 学习者的迁移提醒**：保留明确所有权、接口契约和资源清理习惯，但不要移植确定性析构、对象内存地址身份或同步局部变量的全部直觉。React 是按渲染快照、组件身份和订阅协议运行。

---

<span style="background-color:rgb(255, 249, 227)">四：动手练习</span>

按顺序完成：新增两个同名任务 → 切换完成状态 → 删除其中一个 → 切统计页面 → 返回 → 检查总数 → 刷新观察重置。随后模拟请求慢、失败、连续切换条件，确认旧结果不会污染当前界面。

> [!success]- 参考答案
> 记录每一步的输入、更新入口与预期输出。发现错误时先定位数据流环节，再决定修模型、依赖、请求生命周期还是构建配置。
