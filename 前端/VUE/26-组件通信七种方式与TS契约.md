# Vue3：组件通信七种方式与 TS 契约

> **版本口径**：Vue3＋TypeScript 主线；旧 Vue2/Options API 保留为迁移对照，不与 Vue3 API 混用。
> **来源边界**：已核验课程分集标题；以下原理、示例与练习为结合官方文档自主编写，不是视频逐字稿。

---

<span style="background-color:rgb(255, 249, 227)">一：概念</span>

组件通信不是“七种都用一遍”，而是按所有权、距离和接口显式程度选。状态应有清楚的修改入口；越隐蔽的通信越难定位数据来源。

| 方式 | 适用范围 | 边界 |
| --- | --- | --- |
| props | 父到子输入 | 不推荐子直接改父业务数据 |
| 自定义事件 | 子向父通知意图 | 不自动任意跨层冒泡 |
| mitt 等事件总线 | 解耦事件通知 | 需要取消订阅；事件不是持久状态 |
| 组件 v-model | 配套值与更新事件 | 明确模型名、载荷和更新责任 |
| attrs | 透传未声明属性/监听器 | 多根节点需明确透传目标 |
| refs/parent | 有意暴露命令式能力 | 强耦合，不当常规状态通道 |
| provide/inject | 某个子树的依赖 | 注入可缺失，类型与作用域都要处理 |

---

<span style="background-color:rgb(255, 249, 227)">二：写法与执行过程</span>

```ts
// counter-key.ts
import type { InjectionKey, Ref } from 'vue';
export interface CounterContext {
  count: Readonly<Ref<number>>;
  increment: () => void;
}
export const counterKey: InjectionKey<CounterContext> = Symbol('counter');
```

父组件 `provide(counterKey, { count: readonly(count), increment })`，子组件 `inject(counterKey)` 后先检查是否存在。让子组件调用 increment，而不直接改 count，修改规则集中在所有者。

组件模型可用 `defineModel<string>({ required: true })`（Vue3.4+），或显式写 `modelValue` 与 `update:modelValue`。必须能解释两者的同一协议，才能理解课程中的旧写法。

---

<span style="background-color:rgb(255, 249, 227)">三：对照与易错点</span>

`defineExpose` 决定 script-setup 组件对父 ref 暴露哪些能力。父 ref 挂载前为 null，方法调用也要处理生命周期。attrs 不是一个自动深响应式的全局状态对象，不要用它取代清楚的 props。

<span style="background-color:rgb(255, 249, 227)">四：动手练习</span>

删除任务应该走 props、事件总线还是子组件直接改父数组？

> [!success]- 参考答案
> 常规父子关系由父传任务，子 emit('remove', id)，父按 id 更新数组。只有跨范围的真实需求才考虑总线/状态库。
